1. The Multi-Pass Waterfall Architecture

Standard enterprise systems fail when attempting single-pass matching because real-world banking feeds introduce asynchronous settlement lags and penny rounding noise. Our engine deploys a 4-tier waterfall hierarchy:

Pass 1 (Exact):          Account + Reference Key + Currency + Value Date + Exact Amount
Pass 2 (Tolerance):      Account + Reference Key + Currency + Value Date ±1d + Amount Diff ≤ $0.05
Pass 3 (Timing Lag):     Account + Reference Key + Currency + Value Date ±2d + Exact Amount
Pass 4 (Partial Match):  Account + Reference Key + Currency + Amount Variance > $0.05 (Root Cause Tagged)

2. Mathematical & Partitioning Invariants

To satisfy SOX 404 internal control scrutiny, the engine enforces strict mutually exclusive partitioning. No transaction can ever exist in multiple buckets:

  • Conservation Identity: $\text{Total Internal Records} = \text{Matched} + \text{Partial} + \text{Unmatched Internal}$
  • Sign Inversion Protocol: In internal ERP, debits are positive (cash inflow). In external banking SWIFT MT940 statements, credits are negative (bank's payable to customer). Reconciliation condition strictly evaluates: $\text{Internal Amount} + \text{External Amount} \approx 0$.
  • Remediation Double-Entry: Generated remediation entries strictly enforce $\sum \text{Debits} = \sum \text{Credits}$ to the exact cent before posting to the General Ledger.
